# Flutter To-Do (BLoC + Firebase)

A simple, beginner-friendly To-Do app built to learn **Flutter UI**, **BLoC state management**, **Firebase Authentication**, **Cloud Firestore CRUD** and **Firebase Cloud Messaging**.

Each user only sees their own tasks.

## Features

- Register, login and logout (Email/Password) with friendly error messages
- Create, read, update and delete tasks
- Mark tasks as completed (completed tasks look different)
- Optional description and due date (overdue tasks are highlighted)
- Live updates: the list refreshes automatically through Firestore snapshots
- Delete confirmation dialog, loading indicators, empty state, SnackBar errors
- Push notifications with FCM on Android/iOS (automatically skipped on Windows)
- Firestore security rules so users cannot read each other's tasks

## Tech stack

Flutter, Dart, `flutter_bloc`, `equatable`, `intl`, `firebase_core`, `firebase_auth`, `cloud_firestore`, `firebase_messaging`. Firebase is the only backend.

## Architecture

```
UI (pages/widgets)  ->  BLoC  ->  Repository  ->  Firebase
```

- Widgets never talk to Firebase. They send **events** to a BLoC.
- A BLoC calls a **repository** and emits a **state**.
- `BlocBuilder` redraws the UI, `BlocListener` does one-off things (SnackBar, closing a page), `BlocConsumer` does both.
- `main.dart` shows `HomePage` when `AuthBloc` is `Authenticated`, otherwise `LoginPage`.

## Setup

### 1. Dependencies

```
flutter pub add firebase_core firebase_auth cloud_firestore firebase_messaging flutter_bloc equatable intl
```

This lets pub choose versions compatible with your Flutter/Dart SDK.

### 2. Firebase

1. Create a project at https://console.firebase.google.com
2. Install the tools:
   ```
   npm install -g firebase-tools
   dart pub global activate flutterfire_cli
   firebase login
   ```
3. In the project root run `flutterfire configure`, choose your project and the platforms you need (**windows**, and Android/iOS if wanted). This generates `lib/firebase_options.dart`.
4. Console -> **Authentication** -> Sign-in method -> enable **Email/Password**.
5. Console -> **Firestore Database** -> Create database.
6. Console -> Firestore -> **Rules** -> paste the contents of `firestore.rules` and publish.

### 3. Platform notes

- **Windows:** needs Visual Studio with the "Desktop development with C++" workload. The first build is slow. No Android/iOS/APNs configuration is needed.
- **Android:** add `<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>` to `AndroidManifest.xml`. `google-services.json` is placed by `flutterfire configure`.
- **iOS:** enable Push Notifications and Background Modes (Remote notifications) in Xcode and upload an APNs key in the Firebase console. FCM does not work on the iOS simulator.

## Firestore security rules

See `firestore.rules`. Only a signed-in user can read/write `users/{their own uid}` and its `tasks`, and a task must have a non-empty title.

## Notifications (FCM)

`NotificationService` requests permission, gets the token, and handles foreground, background and tap events. FCM calls are skipped on every platform except Android and iOS, so Windows never throws `MissingPluginException`.

To test on Android/iOS:

1. Run the app on a real device (or an Android emulator with Google Play) and log in.
2. Copy the `FCM token: ...` line from the debug console.
3. Firebase Console -> Messaging -> New campaign -> Notifications -> **Send test message** -> paste the token.
4. App open: a SnackBar appears. App in background or closed: a system notification appears.

### Task reminders (limitation)

FCM only delivers messages sent by a server. The client cannot schedule FCM pushes, and FCM does not create local reminders by itself. This app does not implement due-date reminders yet. Simplest options:

- **On device:** use `flutter_local_notifications` + `timezone` and call `zonedSchedule` when a task with a due date is saved (see the `TODO` in `TaskBloc`).
- **Server side:** a scheduled Cloud Function that finds tasks due soon and sends an FCM message (needs the token stored per user and the Firebase Blaze plan).

## Tests

`test/widget_test.dart` tests the login page and home/add-task pages using fake BLoCs, so no Firebase is needed.

## Troubleshooting

When login/register fails, the message includes the Firebase error code and the full error is printed in the debug console.

| Code | Meaning |
|---|---|
| `operation-not-allowed` | Email/Password is not enabled in Firebase Console |
| `invalid-api-key`, `app-not-authorized` | Wrong or missing `firebase_options.dart`; run `flutterfire configure` again |
| `network-request-failed` | No internet, or a firewall is blocking Firebase |
| `weak-password` | Password shorter than 6 characters |
| `email-already-in-use` | Email already registered; log in instead |
| `permission-denied` (Firestore) | Rules not published, or user not signed in |
